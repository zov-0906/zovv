# iOS HLS 分片缓存

实现采用 Dart loopback HTTP 代理与磁盘缓存；AVPlayer 正常请求 localhost 上的播放清单/分片，由代理校验源站并使用原 HTTPS 凭据访问服务器。远程 TLS 校验保持开启，仅 localhost 配置 ATS 本机访问例外。代理只绑定 IPv4 loopback，随机路径隔离播放器，请求仅允许指定清单、初始化文件与分片名；不开放任意 URL 转发。

缓存目录由 iOS 原生适配层获取，位于 Library/Caches/ZovvVideoSegments 并排除备份。仅当前网关返回有效媒体身份的 HLS 启用；MP4、未知来源、无身份及初始化失败保持原网络播放路径。Android 原生缓存不变。

## 规则

- 150MiB 磁盘预算，按最近读取时间淘汰；单个读取响应最多 8MiB，最多 6 个同时代理请求，最多 8 个播放器租约。
- 身份包含服务器校验过的剧集、分集、清晰度和媒体版本，文件名使用 SHA-256；缓存不保存原 URL、令牌或请求头。
- 初始化文件和媒体分片可跨代理重启复用；播放清单每次联网，不缓存动态 EVENT 窗口。
- 相同分片请求合并；完整接收后通过临时文件原子落盘，失败下载不缓存，启动清理中断临时文件。磁盘错误直接返回网络数据。
- AVPlayer 字节范围请求由完整分片内存数据响应；单片下载完成后才交付给 AVPlayer，首段会增加一个分片级的等待，不等整集。这是第一版的明确取舍。
- 清理入口显示实际磁盘占用，有播放器租约或活动请求时不清理；退出后短暂等待尾部请求释放。源站不可用时不承诺完整离线播放，因为清单仍需联网。
- 此缓存依赖 App 的 Dart 引擎及 loopback 服务，不承诺 iOS 后台音视频能力；本轮不新增后台权限。
